Citadel UI

Living: the code wins 2026-11-02 Builds on the survey of the four apps (shared specs/ui-library/survey-2026-11.md) and theme.css (#269) Checked against Citadel 4d99ace + #283

The look and the parts Citadel serves at /apps/_citadel/ui/ for Mandate, Theory of Crafting and Peek Auras, and use itself, so the four stop drifting apart. Every token and part below is drawn live; flip the theme at the top to see both modes. This is the living home (#283): when it and the code disagree, the code wins, and a change to a token, part or rule updates this page in the same commit. The tokens live in public/style.css (served as theme.css by src/theme.ts), the parts in public/ui/, and test/ui-contract.test.ts holds what apps rely on. How apps use it: the citadel:contraption-ui kit skill.

Built so far (#283): the tokens, ui/base.css and ui/markdown.js. The composer (ui/composer.js, #285) and the chat kit (ui/chat.js, #284) are live; their specimens below copy the look, and the code is mountComposer and mountChat. ui/markdown.js ships Citadel's existing markdown look, moved from its style.css; the restyle in the Markdown specimen (tables in a box, 22/18/16 headings) isn't built yet.

        ✕ On a redraw, a new message, or out of another field

        Someone typing in search, a card or a setting loses their place. On a phone ((pointer: coarse) or 800px and under) it pops the keyboard over the chat on every open.

        13. A status change moves nothing

        Cara, 2026-11-04: set up rules that make sure status changes like that dont move any UI elements. Busy, saved, an error, a counter, a label swap: reserve the space (a status line, a steady label) or overlay it. Press each Save.

        ✓ A status line and a steady label

        This line stays put.

        The line is there, empty, before anything is said; the button is as wide as "Saving…" all along.

        ✕ Text that appears and a label that grows

        This line jumps.

        "Next" slides right as the label grows; the page under the message drops a line when it shows and climbs back when it goes.

        14 to 21. The basics

        Accessibility, layout and feedback rules mined from ui-ux-pro-max's UX guidelines (MIT; #345, Josh: Mine it, don't install). Written out in citadel:contraption-ui, "The rules"; no live demo yet.

        • 14. Keyboard and screen reader reach everything: real buttons and links, aria-label on icon-only buttons, alt on images, a button way for every drag, sticky bars that never hide focus.
        • 15. Tap targets: 24px each way on desktop, --citadel-control-h on phones, --citadel-space-2 apart.
        • 16. Every field has a label; the right type, inputmode and autocomplete; its error under it; Submit disabled while it's sending.
        • 17. A colour never carries meaning alone.
        • 18. Text is never clipped and never widens the page; prose about 75ch at most; full height in dvh.
        • 19. Empty and failed states say what next.
        • 20. Undo over "are you sure?", and Ctrl-Z with it (toast(text, { undo: { run } })).
        • 21. A view worth coming back to has its own URL.

        22. Every modal is the kit dialog

        Cara, 2026-11-08: the X to close should stay at the top and clicking off the modal should close it. cui-dialog with mountDialogs(): the ✕ stays in view, a backdrop click and Escape close it. Shown live under Basic parts, Dialog.

        23. Clicks never freeze the UI

        Cara, 2026-11-08: assume things will work instantly, but recover later if there was an issue. A click shows its result at once and its request runs behind; other controls stay usable and rapid clicks all count. A failure rolls back that one item with a toast and Retry (the failed toast under Status shows it). optimistic() from ui/optimistic.js does it. Only a result that can't be guessed (a calculation, an agent turn) shows busy, on its own region.

        Detail calls made

        The minion's picks on details (#282, 2026-11-02); say if any should go the other way.

        • Type sizes get names too (--citadel-size-body 15, -small 13, -meta 12, -h1…-h3), so apps stop picking their own.
        • The class-only parts ship as one linked ui/base.css (buttons, inputs, chips, notices, spinner, focus ring); the script components keep constructed sheets. A linked file is CSP-clean and needs no import.
